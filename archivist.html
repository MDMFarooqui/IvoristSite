PROJECT 001 / SOFTWARE

Archivist.

IN DEVELOPMENT

Finding something in a large collection of documents shouldn't mean remembering the exact words used in it. Archivist is being built to make that process easier.

THE IDEA

Search your documents by meaning.

Most file searches depend heavily on keywords. That works when you know the exact phrase you're looking for, but it becomes less useful when you only remember the general idea or context.

Archivist is being developed as a local-first document research tool. It processes a user's documents, builds a searchable index, and uses semantic retrieval to find passages related to a question.

The aim is to make personal document collections easier to explore while keeping the work on the user's own machine.

CURRENT DEVELOPMENT

What works so far.

The current build is focused on the core document-search workflow.

01

Document ingestion

Documents can be read and their text extracted so that the contents can be prepared for search.

02

Semantic indexing

Text is converted into embeddings and stored in a searchable index. This makes it possible to retrieve related passages without relying only on exact keyword matches.

03

Local model integration

The project can connect retrieved material to a locally run language model, allowing users to explore the results in more detail.

WHERE WE WANT TO TAKE IT

From search tool to research workspace.

The current version is a starting point. We want to develop Archivist into something more useful for people who regularly work with large amounts of information.

That means improving the document workflow, making search results easier to inspect, and giving users better ways to work with the information they find.

Another important part of the direction is keeping the system local-first. Users should have control over their documents and where their information is processed.

These are development goals, not features that are all available today. The project will continue to change as we build and test it.
